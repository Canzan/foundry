# 003 One card frame owns every chrome\-less page
Status: Accepted

## Context

```text
Fifteen templates place their content directly in the shared base layout, which has no page frame at all, so the signed-out forms run edge to edge at desk width with no card, no margin and no product name. The app shell is not available to them: it renders the navigation rail and needs a resolved nav identity, and a shipped read asserts the sign-in screen has neither a rail nor a theme control. The public shortcut page needs the same frame for the same reason.
```

## Decision

```text
Add one frame template that extends the shared base layout and renders a single centred card with the product name as a brand LINE above the page's own heading, and have the signed-out auth family and the new shortcut page extend it. The card's width, surface, border and shadow are one stylesheet block naming existing tokens; the card's max inline size is the only width rule this Request adds, and below the shipped phone breakpoint the card is full width inside the page padding.
```

## Alternatives

```text
Repeat a wrapper div and a product name in each template (rejected: seven owners of one frame, and the next page added forgets it). Reuse the modal dialog surface (rejected: it is a dialog inside a fixed overlay with its own scrim and close control). Put the product name in an h1 (rejected: each page already owns its single h1 and shipped reads select on those headings). Extend the app shell (rejected: a signed-out page cannot resolve a nav identity and must grow no rail).
```

## Consequences

```text
Any later page that must look like Foundry without the rail extends this one frame. The form and label sizing inside the card stays as shipped and belongs to the next Request. One stylesheet edit touches every page, so the stylesheet is renamed to the hash of its new bytes and its three readers move with it in the same commit; the shipped asset layers refuse a half-done rename.
```
