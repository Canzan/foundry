# 001 The project key bound and its sentence have one owner
Status: Accepted

## Context

```text
The project key rule is stated three times: a length check in the domain constructor, a refusal sentence in the domain, a second copy of that sentence in the web handler, and a CHECK in the shipped first migration. The copies have already drifted in capitalisation, and the request to widen the maximum to ten letters has to change every statement at once.
```

## Decision

```text
The bound lives in named constants in foundry-core and the refusal sentence interpolates them; all three refusal arms render one sentence stating the whole 2 to 10 capital letter rule; the web handler renders that sentence rather than restating it, and a new clause of the existing one-source gate fails any second copy in the web, services, api or store crates; the database rule is widened by a new migration that finds the current key_prefix check by its definition, never by its name, and the shipped first migration is not edited.
```

## Alternatives

```text
Change the three numbers in place and leave the sentence stated twice: cheapest now, but it keeps three owners of one rule and the capitalisation drift shows the copies are not kept equal by review. Teach the database rule through a verdict function as the name rule does: more machinery than a one-line shape needs, and the parity test already reads the real verdict. Keep one sentence per refusal arm: leaves a lower-case or one-letter key answered without the length rule, which the product promise asks for.
```

## Consequences

```text
Widening the maximum again is one constant and one migration. The operator can no longer tell from the sentence which arm refused, which also stops the byte-counting order of the length arm from leaking. The gate fails until the handler copy is removed. The migration takes a brief exclusive lock on the projects table and revalidates it, which is safe because every stored key already satisfies the wider rule.
```
