live_replica_gate.qnt - checker receipts (D5, the live-replica gate window
against the beat cadence a running Foundry server keeps).

WHERE. Every command below ran in the shared Lima VM local-dev, the only
environment this project runs tools in, through scripts/test-in-lima.sh from
the repository root, in one foreground call. Each command's own exit status is
on the line after it; nothing is piped between a command and its status.
Tools: quint 0.32.0 and openjdk 21.0.12.1 in the VM; Apalache is not packaged
there and quint fetched it on its first verify.

WHAT RAN ON WHAT. The sha256 below is of these model bytes as they stand,
which now state that the 20 s reload envelope is a checked bound: a server
whose FOUNDRY_INTEGRATIONS_RELOAD_MS exceeds it refuses to start, so no
deployment runs outside the settings this model draws from. The two mutants
were written from the model by one sed each, inside /tmp in the VM, and
deleted after their runs: m8 takes the window as three times the reading
server's own setting, m9 as two beat intervals plus that same setting - the
two windows this design refuses. A [violation] with exit 1 on a mutant is its
kill; the run of neverNearTheWindow is negated on purpose, so its violation is
the witness that the longest gap the model admits comes within one second of
the window.
