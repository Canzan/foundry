## Equivalent mutants (excluded from the denominator)

1. **`:1890:25` `index + 1` → `index * 1`** in `refuses_an_empty_stamp`. The scan now starts at
   the refusal line itself instead of the line after it. That line contains `build stamp is empty`,
   so it can never equal `"fi"` (the `take_while` stays open) and never equal `"exit 1"` (the `any`
   does not match). The result is the same for every input.
2. **`:1931:38` `builder + 1` → `builder * 1`** in the `cargo build` search. The range gains index
   `builder`. That index was chosen by `position(|i| i.keyword == "FROM" …)`, so its keyword is
   `FROM` and it can never satisfy `keyword == "RUN"`. `find` returns the same index.
3. **`:1942:35` `builder + 1` → `builder * 1`** in the adjacent-ARG run. The range gains index
   `builder`. It is walked last in `.rev()`, and the walk only reaches it if every instruction in
   between is an `ARG`. Its keyword is `FROM`, so `take_while(keyword == "ARG")` stops before it.
   `last()` and the `unwrap_or(cargo_build)` fallback are therefore unchanged, including the empty
   case `cargo_build == builder + 1`.

## Survivors analysis

**B4, `build.rs` `rerun_on_nearest_existing -> ()`: genuine survivor.** This function registers the
branch's loose ref, or its nearest existing parent directory when the ref is packed, as a
`rerun-if-changed` path (D11, "the stamp does not go stale"). With it gone, a commit on a branch
changes neither `HEAD` (which still says `ref: refs/heads/<branch>`) nor necessarily
`packed-refs`. The build script would not rerun, and the footer would keep naming the previous
commit. Nothing observes cargo's rerun directives:
- the unit tests only drive `stamp` (`emit_rerun_directives` is `dead_code` in the test module);
- the `rvf` lane compiles the app once per checkout and compares against git at that moment.

Killing it needs a test that runs the build script, or `emit_rerun_directives` with an injectable
sink, against a scratch repository with packed refs, and asserts the emitted paths.

**xtask survivors (4), genuine. Each is a missing fixture, not an unreachable branch:**
- `:1890:25 index - 1`: the scan starts one line too early. It differs from the original when the
  refusal line is preceded by `fi` (a false violation) or by `exit 1` (a false pass), and it panics
  when the phrase is on the first non-comment line. No fixture has either neighbour.
- `:1901:55`: textually this becomes `a || b && c` = `$(date || (`date && starts_with("date "))`,
  so a backtick ``x=`date +%F` `` line is no longer flagged. The `` `date `` branch has no example.
  The `$(date` row and the bare `date …` path are covered.
- `:1919:43`: the builder stage becomes "the first `FROM`, of any name". The fixtures and the
  shipped Dockerfile both open with the builder stage, so nothing tells the two apart. A fixture
  with a stage before `AS builder` (for example a `chef`/planner stage) would kill it.
- `:1984:13`: `keyword == "ARG" || …` makes **any** `ARG` declare every name. A builder stage whose
  adjacent run is `ARG FOUNDRY_STAMP_DATE=` alone (the SHA ARG simply deleted) then passes the
  adjacency check. The existing "late arg" row still fails, but only on its "outside the builder
  stage" message. A fixture that drops one stamp ARG without re-adding it elsewhere, and asserts the
  "does not declare `ARG FOUNDRY_STAMP_SHA=`" message, would kill it.

Under the SLIM scope these go back to `nw-acceptance-designer` as test-strength findings. The
crafter does not author the fixtures. They do not block the gate.
