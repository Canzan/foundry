{# THE CLOSE CONTROL IS THE ONE THING THE TWO CARRIERS CANNOT SHARE, and it shipped shared and DEAD on one of them. `[data-action="close-modal"]` does not mean "close"; it names ONE mechanism — keyboard.js::closeModal() empties `#modal-root` (D-10, adr-modal-close-001). In the popup that IS the close, because the popup lives in that host. On `delete_issue_modal_page.html` there is no `#modal-root` at all, so the listener fired, found a null host, returned, and the x rendered while doing nothing — Priya's only way out of a destructive dialog was the browser Back button. So `close_href` decides the ELEMENT, and it is the only thing that differs: empty on the popup (the button, the shipped mechanism, untouched), set on the page (an anchor back to the issue — cancelling a delete returns you to the thing you decided not to delete). Both are `.modal-close`, so D-13's target-size and focus-ring rules and the acceptance selector cover both without knowing which carrier rendered. The one-partial rule (DDD-6) holds: the COPY, the counts, the confirm form and the undo warning still cannot disagree between the two. #}
